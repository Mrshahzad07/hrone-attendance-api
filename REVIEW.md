# REVIEW.md: Defects Found in the Starter Code

Comprehensive review of the defects identified in the starter `app/main.py`, their impact/symptoms, and the applied fixes.

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |
|---|---|---|---|---|
| 1 | `compute_late_minutes` (lines 33-37) | `replace(hour=..)` on a UTC or naive datetime constructs shift start in the wrong time zone and date. | A punch at 09:35 IST calculates against UTC, yielding huge or negative minutes. | Converted timestamp to IST and built shift start datetime using `attendance_date` and `shift_start_dt` (R1). |
| 2 | `compute_late_minutes` (lines 36-37) | Floors to whole minutes before testing `> 10`. | A punch at 09:40:01 (10 min 1 s) calculates `delta // 60 = 10`, fails `> 10`, and incorrectly returns `0`. | Compare total seconds strictly `> 600` (`GRACE_SECONDS`), then floor to whole minutes (R2). |
| 3 | `compute_late_minutes` (lines 33-37) | No overnight shift support and no millisecond truncation. | A 00:30 punch on a 22:00-06:00 shift computes against the current calendar day instead of the previous day's shift. | Implemented `attendance_date()` and `shift_start_dt()` to properly attribute overnight punches (R1). |
| 4 | `compute_work_hours` (line 41) | Python's standard `round()` uses round-to-even (banker's rounding) on floats. | 28,818 seconds (= 8.005 h) rounds to 8.0 instead of 8.01. | Computed with `Decimal` using explicit `ROUND_HALF_UP` quantization (R4, R8). |
| 5 | `compute_overtime` (lines 44-47) | Subtracts timezone-aware `end` from timezone-naive `punch_out`. | Raises `TypeError: can't subtract offset-naive and offset-aware datetimes`, causing HTTP 500 on punch-out. | Initialized `MongoClient` with `tz_aware=True` and ensured all datetimes are timezone-aware UTC. |
| 6 | `compute_overtime` (lines 44-47) | No 30-minute minimum threshold; overnight shift end date not advanced. | Punch-out at 18:45 returns 15 minutes instead of 0; overnight end time falls on previous calendar day. | Enforced `OVERTIME_MIN_MINUTES = 30` (R3); advanced overnight end by +1 day via `shift_end_dt()`. |
| 7 | `create_employee` (lines 78-85) | Check-then-insert race condition (`find_one` then `insert_one`); zero input validation. | Two concurrent requests with the same `emp_code` both succeed (201). Malformed emails or invalid codes accepted. | Rely on unique MongoDB index on `emp_code` catching `DuplicateKeyError` -> 409; enforced Pydantic regex/date validations. |
| 8 | `create_employee` (line 82) | `datetime.now()` stores naive local time; `created_at` leaks as raw Python datetime object. | API output leaks datetime object instead of epoch milliseconds; time zone varies by machine. | Stored UTC datetime (`now_utc()`); serialized `created_at` to integer epoch milliseconds via `dt_to_ms()`. |
| 9 | `list_employees` (line 93) | Off-by-one pagination: `skip = page * page_size` skips the first page when `page=1`. | Requesting `page=1` skips the first 20 records; page 1 items are never seen. | Corrected formula to `(page - 1) * page_size` (R10). |
| 10 | `list_employees` (lines 90-96) | `total` counts the whole collection ignoring the department filter; no sort order; unbounded pagination. | Filtering by department returns total of all departments; unstable order; `page=0` or `page_size=10000` accepted. | Count filtered query `count_documents(q)`; sort by `emp_code ASC`; added `Query(ge=1, le=100)` bounds. |
| 11 | `punch_in` (lines 101-102) | Missing existence check for employee (`emp["shift_start"]` on `None`). | Unknown `emp_code` throws `TypeError: 'NoneType' object is not subscriptable`, causing an internal 500. | Checked `if not emp: raise HTTPException(404, "employee not found")`. |
| 12 | `punch_in` (lines 66, 100) | `status` accepts arbitrary unvalidated strings including `ABSENT` and `LEAVE`. | Punch-in can record `status="ABSENT"`, which contract forbids. | Constrained input status to `PresenceStatus = Literal["PRESENT", "WFH", "ON_DUTY"]`. |
| 13 | `punch_in` (line 102) | `datetime.fromtimestamp()` uses server local time; `if body.punched_at` treats 0 as false; accepts floats/seconds. | Punches get corrupted by local system timezone; seconds-looking timestamps or float inputs accepted. | Converted via `ms // 1000` with `tz=timezone.utc`; constrained with `StrictInt` range (100B to 4102B). |
| 14 | `punch_in` (lines 104-106) | Check-then-insert race condition for same day punch-in. | Two concurrent punch-ins for the same day both pass `find_one` and insert duplicate documents. | Enforced compound unique index `{"emp_code": 1, "date": 1}` catching `DuplicateKeyError` -> 409. |
| 15 | `punch_in` (lines 103, 119) | Date derived from raw timestamp ignores R1 overnight rules; response leaks MongoDB `ObjectId`. | A 00:30 punch on an overnight shift is recorded under the wrong date; `id` is returned in response. | Computed date via `attendance_date()`; sanitized response via `att_out()` (never leaks `_id` or `id`). |
| 16 | `list_attendance` (lines 144-147) | Fetches entire collection into memory with `list(db.attendance_logs.find(q))` and sorts in Python. | Severe memory exhaustion and high latency on large datasets (~100k records). | Pushed sort, skip, and limit down to MongoDB utilizing compound indexes and `count_documents(q)`. |
| 17 | `list_attendance` (lines 125-150) | Incomplete sort order; no validation of date parameters (`date_from > date_to`); legacy records miss default fields. | Unstable tie-breaking; inverted date ranges execute queries; missing `history` or `half_day` raises `KeyError`. | Sorted by `[("date", -1), ("emp_code", 1)]`; validated date range (422 on error); provided defaults via `att_out()`. |
| 18 | `/health` (lines 72-74) | Returns `{"status": "ok"}` unconditionally without checking MongoDB connectivity. | Health check returns 200 even when database is completely down or unreachable. | Pings database via `client.admin.command("ping")` and returns 503 on `PyMongoError`. |
| 19 | Startup / Client (lines 22-28) | No indexes created at startup; default PyMongo client returns naive datetimes. | Collection scans on every query; race conditions cause duplicates; aware/naive datetime conflicts. | Configured `tz_aware=True`; added FastAPI `lifespan` handler to idempotently create all 7 required indexes. |

---

### Examined and Verified Fine
- **`IST = timezone(timedelta(hours=5, minutes=30))`**: Correctly represents UTC+05:30.
- **`load_dotenv()`**: Placed at file top; does not override existing system environment variables, adhering to the rule that real environment variables take precedence.
- **Pydantic extra fields handling**: Pydantic v2 ignores unmodeled fields by default, satisfying the requirement that client-sent derived fields (such as `work_hours`) are ignored.
- **Route paths**: Base route paths (`/health`, `/employees`, `/attendance`) conform to the contract.
